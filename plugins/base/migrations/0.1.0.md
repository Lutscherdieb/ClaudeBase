# Migration to v0.1.0

## Why
Most of 0.1.0 is mechanical, and `/base:sync` applies it: the `enabledPlugins` key-path, two region rev bumps, and the new `tooling` region. Two follow-ups need a person to decide. First, some projects already fixed the `enabledPlugins` shape by hand and recorded that as a divergence. Second, the lessons this release harvested still sit in the projects' learning logs as `candidate`, so `/base:promote` would offer them again.

## Steps
1. **Settings shape.** After sync, open `.claude/settings.json` and confirm `enabledPlugins` is an object (`{"base@claudebase": true}`). If `.claude/base-manifest.json` `divergences` has an entry about the `enabledPlugins` / settings shape, delete it: the seed now agrees with the project, so it no longer diverges.
2. **New `tooling` region.** Sync proposes inserting `BASE:tooling` right after the `doctrine-verify` region in `CLAUDE.md`. Accept it. If the project already wrote an equivalent heredoc rule in its own words (in CLAUDE.md or as a tooling entry in the learning log), keep whichever reads better and remove the duplicate, so the rule has one home.
3. **Harvested lessons.** In `.claude/learning-log.md`, find every `scope: generic` entry whose rule is now covered by one of these 0.1.0 CHANGELOG lines:
   - the seed's `enabledPlugins` shape;
   - checks that derive their list from the source of truth, strip comments, or are proven with a planted positive (including ledger and template-row false passes and `grep -E` patterns that silently exit "clean");
   - committed generator output printing repo-relative paths;
   - script payloads kept out of heredocs.

   Set each one to `status: merged` and add `- merged: base 0.1.0 (harvested 2026-11-22, direct Base edit, no PR)`.

## Verification
- `python3 -c "import json; d=json.load(open('.claude/settings.json')); assert isinstance(d['enabledPlugins'], dict)"` exits 0.
- `grep -c 'BASE:tooling:v1 START' CLAUDE.md` prints `1`.
- `/base:doctor` lists none of the entries from step 3 as promotion-ready.

## If you skip it
Step 1: a stale divergence keeps `/base:doctor` reporting a "Base didn't fit" that no longer exists. Step 2: the project misses the heredoc workaround, or ends up with two copies of it. Step 3: `/base:promote` keeps offering lessons that are already in Base. That costs a review round, but nothing breaks.
